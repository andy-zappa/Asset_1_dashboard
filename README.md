## 1. 시스템 개요 및 아키텍처
* **서버:** Oracle Cloud (4 OCPU, 24GB RAM, Linux 9.7)
* **구조:** `collector.py` (수집) → `.json` (저장) → `api_server.py` (서빙) → `andy_zappa.py` (프론트엔드 UI)
* **프로세스 관리:** `watchdog.sh`를 통해 백그라운드 프로세스 무중단 감시

## 2. 파일별 상세 역할
* `api_server.py`: FastAPI(8000포트). 데이터 서빙 및 Admin 설정 업데이트.
* `collector.py`: 10초 주기 데이터 수집 루프. `history_db.json` 장부 기록.
* `andy_tax_advantaged_v1.py`: KIS API 기반 절세계좌 수집.
* `andy_taxable_v1.py`: KIS + Yahoo Finance 기반 일반계좌 수집.
* `andy_crypto_v1.py`: Upbit API 기반 코인 수집 (보안 복호화 로직 포함).
* `andy_zappa.py`: Streamlit 기반 통합 대시보드 메인 UI. [Architect & UI by Andy]

## 3. 🚨 AI 코딩 철칙 (Hallucination 방지)
1.  **핀포인트 수정:** 지시받은 부분만 수정하며, 임의로 기존 로직을 리팩토링하지 말 것.
2.  **들여쓰기 금지:** HTML/CSS 코드를 출력할 때는 무조건 좌측에 딱 붙여서(들여쓰기 없이) 출력할 것.
3.  **출력 제한:** 코드가 500줄을 넘어가면 500줄 단위로 끊어서 출력할 것.
4.  **정밀도:** 금융 대시보드 특성상 1px 단위의 정렬과 Apple San Francisco 폰트 기반의 UI 디자인을 유지할 것.
5.  **확인 우선:** 로직이 충돌하거나 불확실한 경우 추측하지 말고 사용자에게 먼저 질문할 것.

## 4. 손익 계산 규칙 (대시보드 [1] / [2])

대시보드의 손익은 분모가 다른 두 기준으로 나뉘며, 두 기준 모두 예수금 처리가 다르다. 근거는 사용자 확정 규칙(2026-10-20)과 2026-10-20 일반계좌 화면 캡처 수치다.

| 구분 | 질문 | 총 자산 | 분모 | 손익 | 손익률 |
|---|---|---|---|---|---|
| [1] 투자원금 대비 총 자산의 증감 | 계좌에 넣은 돈 대비 계좌 전체가 얼마나 늘었나 | 평가금액 + 예수금 | 투자원금 (예수금 포함) | 총 자산 − 투자원금 | 손익 ÷ 투자원금 |
| [2] 매입금액 대비 종목별 손익(예수금 제외) | 지금 종목에 투자된 돈 대비 종목 손익은 얼마인가 | 평가금액 + 예수금 | 매입금액 = 총 자산 − 예수금 − 총 손익 | Σ 종목별 평가손익 | 손익 ÷ 매입금액 |

### 4.1 데이터 출처

| 항목 | 출처 | 비고 |
|---|---|---|
| 투자원금 `{키}_PRINCIPAL` | 관리자 '자산정보요약' 투자원금, 서버 `/get_config` | 입출금 시에만 사용자가 수기 갱신 |
| 예수금 `{키}_CASH` | 서버 `/get_config` | 현금성 자산(미투자 현금) |
| 평가금액·평가손익 | 서버 `/taxable`, `/tax_advantaged`, `/crypto` | 실시간 수집 |
| 암호화폐 미투자 현금 | 서버 `/crypto`의 `total_krw` (110,000,000원) | 사용자 설정 예외 |

### 4.2 계좌 유형별 적용

| 계좌 | [1] 투자원금 | [2] 매입금액 |
|---|---|---|
| 일반 (DOM1, DOM2, USA1, USA2) | 관리자 자산정보요약 원금 | 종목별 `평가금액 − 평가손익`을 합산 (예수금·합계행 제외, 해외는 환율 환산) |
| 절세 (DC, IRP, PENSION, ISA) | `{키}_PRINCIPAL` | 종목별 `평가금액 − 평가손익`을 합산 (`_tax_buy_amount`) |
| 암호화폐 | Admin 투자원금 `CRYPTO_PRINCIPAL` (112,872,566원, 현금 110,000,000원 포함) | 총 자산 − 미투자 현금 − 총 손익 (2,872,566원 수준) |

### 4.4 과거 데이터와 기록 기준

- 자산·원금·예수금의 과거 이력은 저장되어 있지 않다. 이전 날짜는 손익 이력만 있어 [1]·[2]를 재구성하지 않는다.
- 일별 기록은 서버 `collector.py`의 `save_daily_history()`가 `history_db.json`에 날짜 키(KST)로 남긴다. 같은 날짜는 10초 주기로 덮어써져 그날 마지막 값이 남는다.
  - 저장 항목: `{키}_PRINCIPAL`, `{키}_CASH` (서버 `master_config.json`에서 읽음, 키 `DOM1 DOM2 USA1 USA2 DC IRP PENSION ISA CRYPTO`), `{키}` 평가손익, `{키}_asset` 총자산, `{키}_BUY` 매입금액 (일반·절세는 종목별 `평가금액 − 평가손익` 합, 암호화폐는 `총자산 − 미투자현금 − 손익`)
  - 설정 값이 없으면 `null`로 기록한다.
- [1] 7/15/30일전: `오늘 − N일`의 기록에서 `{키}_asset − {키}_PRINCIPAL`을 계산한다. 해당 날짜 기록이 없으면 `-`로 표시하며 추정하지 않는다.
- 총 자산 추이 차트: 기록이 있는 날짜만 총자산·수익률을 그리고, 없는 날짜는 선을 끊는다. 총평가손익은 손익 이력으로 그린다.
  - 2026-10-20 서버 `/home/opc/collector.py`에 반영했다. 이전 파일은 `collector.py.bak_20261020`로 백업되어 있다. 반영 이전 날짜에는 원금·예수금 기록이 없다.
- 대시보드 화면의 `ℹ️ 손익 계산 기준 설명` 펼침 메뉴에 같은 내용을 넣었다 (`andy_test_0923.py`의 `PNL_BASIS_HELP`).
